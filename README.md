# TilaPulse

TilaPulse is a prototype tilapia pond monitoring system. One physical ESP32 sends temperature, pH, and dissolved oxygen readings to a FastAPI backend. The Flutter app displays the latest reading, while the backend can run an LSTM and BOCPD risk pipeline over a sensor sequence.

## Project Flow

```text
ESP32
  -> POST /api/readings
  -> FastAPI validation and Philippine timestamp
  -> SQLite device-scoped reading storage
  -> POST /api/predict with a device_id
  -> missing-value handling and normalization
  -> fixed-length sliding window
  -> unidirectional PyTorch LSTM probability
  -> BOCPD change-point probability
  -> weighted risk score
  -> Flutter app consumes the JSON response
```

The backend identifies devices by `device_id`. Readings are persisted in SQLite at `server/data/tilapulse.db` and each device is auto-registered on its first accepted reading. The Flutter app currently selects `pond-1` by default.

A reading contains:

- `device_id`
- `temperature`
- `ph`
- `dissolved_oxygen`
- `timestamp` generated by the backend

POST requests require the device's shared key in the `X-Device-Key` header. GET routes are open for the read-only Flutter app.

## Repository Structure

```text
server/
  app/
    main.py             FastAPI application and health/root routes
    schemas.py          Reading and prediction request/response models
    db.py               SQLite engine, sessions, and declarative base
    models.py           Reading and device SQLAlchemy models
    readings.py         Device-scoped reading and device routes
    prediction.py       LSTM + BOCPD fusion service and prediction route
    preprocessing.py    Missing values, normalization, and model windows
    lstm.py             Unidirectional PyTorch LSTM construction/loading
    bocpd.py            Online change-point probability detector
    synthetic_data.py   Development-only labelled sequence generator
    core/config.py      Environment-backed settings and device keys
  models/lstm_model.pt  Development model checkpoint
  scripts/train_lstm.py Synthetic model training script
  tests/                Backend API and ML tests

tilapulse/
  lib/services/sensor_api.dart Flutter HTTP client for the latest reading
  lib/app_shell.dart     Flutter dashboard screens
```

## Backend Routes

| Method | Route | Purpose |
| --- | --- | --- |
| `GET` | `/` | Basic API information |
| `GET` | `/api/health` | Health check |
| `POST` | `/api/readings` | Validate and store one sensor reading |
| `GET` | `/api/readings?device_id=pond-1` | Return that device's readings |
| `GET` | `/api/readings/latest?device_id=pond-1` | Return that device's latest reading |
| `GET` | `/api/readings/{device_id}` | Return readings for a device |
| `GET` | `/api/devices` | List registered devices |
| `POST` | `/api/predict` | Run the device-scoped LSTM + BOCPD pipeline |

Device listing and mock-data API routes were intentionally removed.

## Running the Backend

From the `server` directory:

```bash
python -m venv .venv
```

Windows PowerShell:

```powershell
.venv\\Scripts\\Activate.ps1
pip install -r requirements.txt
python -m uvicorn app.main:app --reload
```

For an ESP32 on the same Wi-Fi network, bind the API to the computer's LAN interfaces:

```powershell
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

The API is then reachable from the computer at `http://localhost:8000` and from the ESP32 at `http://<computer-lan-ip>:8000`. Swagger UI is available at `/docs`, and the OpenAPI document is at `/openapi.json`.

For local development, create `server/.env` with a key you choose:

```env
DEVICE_KEYS={"pond-1":"replace-with-a-private-test-key"}
```

Run tests with:

```bash
python -m pytest -q
```

## Reading API

Submit a reading:

```bash
curl -X POST http://localhost:8000/api/readings \
  -H "Content-Type: application/json" \
  -H "X-Device-Key: replace-with-a-private-test-key" \
  -d '{
    "device_id": "pond-1",
    "temperature": 29.5,
    "ph": 7.2,
    "dissolved_oxygen": 5.8
  }'
```

Response:

```json
{
  "temperature": 29.5,
  "ph": 7.2,
  "dissolved_oxygen": 5.8,
  "timestamp": "2026-09-18 14:30:00"
}
```

The timestamp uses Philippine local time and the format `YYYY-MM-DD HH:MM:SS`.

## ESP32 Integration

In `tilapulse_device.ino`, replace `YOUR_WIFI_NAME`, `YOUR_WIFI_PASSWORD`, `YOUR_COMPUTER_LAN_IP`, and `YOUR_DEVICE_KEY`. The `API_URL` must use the computer's LAN IP, not `localhost`. The device sends one authenticated reading every two seconds to `POST /api/readings`.

The device key must match the `DEVICE_KEYS` entry in `server/.env`, for example:

```env
DEVICE_KEYS={"pond-1":"replace-with-a-private-test-key"}
```

Get the latest reading:

```bash
curl "http://localhost:8000/api/readings/latest?device_id=pond-1"
```

Get recent history:

```bash
curl "http://localhost:8000/api/readings?device_id=pond-1&limit=20"
```

## Prediction Pipeline

`POST /api/predict` accepts a `device_id` and loads that device's persisted readings. The preprocessor fills missing values using the previous available value, normalizes the three sensor features, and pads or trims the sequence to the configured window size. The default window size is 20.

The same normalized window is sent to both models:

- The unidirectional PyTorch LSTM returns `lstm_probability`.
- BOCPD processes each window row and returns `bocpd_probability`.
- The final score is `0.7 * lstm_probability + 0.3 * bocpd_probability` by default. These weights are configurable through `prediction_alpha` and `prediction_beta`.

Example request:

```bash
curl -X POST http://localhost:8000/api/predict \
  -H "Content-Type: application/json" \
  -d '{
    "device_id": "pond-1"
  }'
```

Example response:

```json
{
  "lstm_probability": 0.72,
  "bocpd_probability": 0.61,
  "risk_score": 0.687,
  "synthetic_model_notice": "A checkpoint trained on SYNTHETIC data is for software development only, not real disease evidence."
}
```

The endpoint returns HTTP 503 with training instructions if `models/lstm_model.pt` is unavailable.

## Synthetic Data and Training

Synthetic data is not an API feature and must not be treated as real disease evidence. `server/app/synthetic_data.py` generates reproducible labelled sequences representing:

- normal conditions
- gradual deterioration
- sudden changes
- recovery

Train the development checkpoint from the `server` directory:

```bash
python scripts/train_lstm.py
```

The script generates 200 sequences, preprocesses them into 20-step windows, trains the LSTM for 20 epochs, and writes `server/models/lstm_model.pt`. A real deployment requires an appropriately labelled farm dataset and proper evaluation; the synthetic checkpoint is only for software development.

## Flutter Integration

The Flutter HTTP client is in `tilapulse/lib/services/sensor_api.dart`. It calls `GET /api/readings/latest` and parses `temperature`, `ph`, `dissolved_oxygen`, and `timestamp`. The dashboard uses these values in `tilapulse/lib/app_shell.dart`.

For local development:

- Flutter Web or desktop usually uses `http://localhost:8000`.
- The Android emulator uses `http://10.0.2.2:8000`.
- A physical phone should use the computer's LAN IP address.

The Flutter client fetches live readings, device-scoped predictions, and registered device metadata. If no ESP32 is connected yet, use the authenticated `POST /api/readings` curl command above to seed a test reading through the real ingestion path.
